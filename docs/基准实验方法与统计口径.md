# 基准实验方法与统计口径（当前实现）

本文档总结当前仓库中“metadata 驱动优化”实验的实际执行方法，基于 `scripts/bench/` 下的脚本行为，而非理想化流程。

## 1. 实验目标与对比维度

当前 nightly 全量实验由 `scripts/bench/run_full_nightly.py` 驱动，按基准逐一采集三个维度：

1. **运行时性能（performance）**：`with metadata` vs `without metadata`。
2. **编译时延（compile_latency）**：仅触发优化编译路径，比较 metadata 额外开销。
3. **二进制代码生成（binary_codegen）**：比较优化后汇编指令规模与差异。

统一输出到：

- `tmp/bench/nightly-full-results.jsonl`（追加式结构化结果流）
- `tmp/bench/nightly-full.log`（人类可读日志）

---

## 2. 工具链与职责

## 2.1 入口与编排

- `scripts/bench/run_full_nightly.py`
  - 全量枚举 `scripts/bench/benchmarks/*.ts|*.js`
  - 对每个基准串行执行性能 / 编译时延 / 汇编对比
  - 记录每个维度的状态、关键指标、stdout/stderr tail

- `scripts/bench/run_pipeline.py`
  - 单基准/批量的性能对比主入口
  - 自动处理 TS 基准：可选 wrappers 预处理 + TS→JS + metadata 生成
  - 调用 `run_bench.py` 分别执行 with/without metadata

## 2.2 数据准备与元数据生成

- `scripts/ts_locals_to_wrappers.js`
  - 对 TS 基准做局部变量 wrapper 预处理（默认开启，可 `--no-wrapper-preprocess` 关闭）

- `scripts/ts_to_metadata.js`
  - TS 编译到 JS
  - 基于 TS 类型注解与 Source Map 生成 metadata
  - metadata 文件按 JS 内容 SHA256 命名

## 2.3 性能测量

- `scripts/bench/run_bench.py`
  - 自动生成 harness（`setup()` → warmup → measured loop → `teardown()`）
  - 优先用 `perf stat -x ,` 采集 `cycles`（可扩展 `instructions`）
  - 支持固定 CPU 核、nice、run 间 sleep、离群值过滤、稳定性判断

## 2.4 编译开销测量

- `scripts/bench/measure_compile_cost.py`
  - 构造“轻量优化触发”harness（`%PrepareFunctionForOptimization` / `%OptimizeFunctionOnNextCall`）
  - 交错执行 with/without，降低时间漂移偏差
  - 输出 paired delta、bootstrap CI、结论分类

## 2.5 代码生成规模测量

- `scripts/bench/generate_bench_assembly.py`
  - 生成 with/without metadata 的优化后汇编
  - 支持 `target` 或 `all-business`（统计所有业务函数）
  - 输出 `comparison.md` + `comparison.json`

- `scripts/bench/measure_codegen_size.py`
  - 汇总 `*_with.asm` 与 `*_without.asm` 的非空行数差异
  - 产出 JSON + JSONL 统计

## 3. 基准集与数据生成

基准目录：`scripts/bench/benchmarks/`，当前包含（见 `scripts/bench/benchmarks/README.md`）：

- Matrix Multiply
- Base64 Codec
- Image Convolution
- Crypto-SHA256
- N-Body
- LZ77 Compression
- Dijkstra Routing
- Splay Tree
- Radix Sort
- JSON Parser
- Richards
- DeltaBlue

每个基准需导出：

- `setup()`（可选）
- `bench()`（必需）
- `teardown()`（可选）

数据生成原则（从现有实现归纳）：

1. **确定性输入**：`setup()` 中以固定种子/固定规则构造数据，减少随机扰动。
   - 示例：`matrix-multiply.ts` 中使用固定线性递推填充矩阵。
   - 示例：`radix-sort.ts` 中用固定 LCG 序列初始化数组。
2. **热点隔离**：`bench()` 聚焦核心计算路径，返回 checksum/组合值避免被 DCE。
3. **生命周期清理**：`teardown()` 回收大型数组/对象，降低跨轮次污染。

## 4. 预热与测量流程

## 4.1 运行时性能（`run_bench.py`）

默认流程：

1. `setup()`（若存在）
2. 预热循环：`__runLoop(warmup, inner_loop)`
3. 可选 `gc()`（`--force-gc-before-measure`）
4. 正式测量循环：`__runLoop(iterations, inner_loop)`
5. `teardown()`（若存在）

默认参数来自 `scripts/bench/config/defaults.json`：

- `warmup=2000`
- `iterations=3000`
- `inner_loop=40`
- `repeats=5`
- `drop_first=4`
- `mad_z=3.0`
- `sleep_ms=25`
- `cpu_core=2`
- `stability_cv_threshold=0.03`
- `perf_events=cycles`

nightly 性能维度中，`run_full_nightly.py` 会对每个基准生成临时 override（默认 `perf_repeats=30`，且 `drop_first=max(1,repeats//4)`）。

## 4.2 编译时延（`measure_compile_cost.py`）

目标是尽量只测“触发优化编译”的成本：

1. 构造 compile harness，调用 `%PrepareFunctionForOptimization` 等原语。
2. 先执行 `warmup_pairs` 组交错预热（默认 nightly 为 2 组）。
3. 再执行 `repeats` 组交错采样（默认 nightly 为 30 组）。
4. 每组都包含 with/without 两次，且顺序交替（AB/BA）以平衡时间漂移。

## 4.3 代码生成（`generate_bench_assembly.py`）

1. 构造优化 harness，触发目标函数优化。
2. 在两种模式下抓取 `--print-opt-code` 输出。
3. 归一化地址并比较：指令行数、指令字节数、差异行数。
4. 可选 `--trace-ir` 输出 IR 日志以辅助解释差异。

## 5. 统计学方法（当前脚本口径）

## 5.1 描述统计

`run_bench.py` 与 `measure_compile_cost.py` 都输出：

- `mean`
- `median`
- `stdev`（总体标准差，`statistics.pstdev`）
- `cv = stdev / mean`
- `min/max`

其中 CV 用于稳定性判断：`cv <= stability_cv_threshold` 记为稳定。

## 5.2 去噪与离群处理（运行时性能）

在 `run_bench.py` 中：

1. **丢弃前 N 次**：先做 `drop_first`。
2. **MAD 离群过滤**：对剩余样本按中位数绝对偏差（MAD）计算 robust z-score。
3. **阈值过滤**：`|z| > mad_z` 视为离群并剔除。

对应 robust z-score 公式：

$$
z_i = 0.6745 \cdot \frac{x_i - \mathrm{median}(X)}{\mathrm{MAD}(X)}
$$

## 5.3 配对差值与置信区间（编译时延）

在 `measure_compile_cost.py` 中：

1. 以 pair 为单位计算差值：

$$
\Delta_i = t^{(with)}_i - t^{(without)}_i
$$

2. 采用 **bootstrap on median** 估计 95% CI（默认 2000 次，nightly 默认 3000 次）。
3. 使用固定随机种子 `42` 保证可复现。

分类逻辑（`classify_delta`）：

- `overhead`：CI 下界 `> tolerance_sec`
- `speedup`：CI 上界 `< -tolerance_sec`
- `neutral`：CI 跨越容忍区间

容忍区默认按 baseline（without 中位数）的 0.1%：

$$
\mathrm{tolerance\_sec} = 0.001 \times \mathrm{median}(t^{(without)})
$$

## 6. 结果产物与追踪

常见输出：

- 性能：`tmp/bench/results-*.json`、`tmp/bench/pipeline-report-*.json`、`tmp/bench/bench-results.jsonl`
- 编译时延：`tmp/bench/compile-cost-*.json`、`tmp/bench/compile-cost.jsonl`
- 汇编对比：`docs/assembly/benchmarks/<bench>/comparison.{md,json}`
- 全量 nightly：`tmp/bench/nightly-full-results.jsonl`、`tmp/bench/nightly-full.log`

JSONL 采用追加写入，支持长期趋势分析与失败复盘（每条记录都带运行时间和关键命令上下文）。

## 7. 推荐复现实验命令

1) 单基准完整性能对比：

```bash
python3 scripts/bench/run_pipeline.py \
  --bench scripts/bench/benchmarks/matrix-multiply.ts
```

2) 单基准编译时延测量（配对 + CI）：

```bash
python3 scripts/bench/measure_compile_cost.py \
  --bench scripts/bench/benchmarks/matrix-multiply.ts \
  --repeats 30 \
  --warmup-pairs 2 \
  --bootstrap-iterations 3000
```

3) 单基准汇编对比（业务函数全量统计）：

```bash
python3 scripts/bench/generate_bench_assembly.py \
  --bench scripts/bench/benchmarks/matrix-multiply.ts \
  --stats-scope all-business
```

4) 跑 nightly 三维度全集：

```bash
python3 scripts/bench/run_full_nightly.py
```

## 8. 口径说明（避免误读）

1. 性能维度主指标默认是 `cycles`，`instructions` 仅在配置中显式开启时生效。
2. 编译时延是“优化触发场景”成本估计，不等同于完整应用启动/运行总时延。
3. 汇编行数下降不必然意味着实际 wall-time 同比例下降，需结合 performance 维度联合判断。
4. 强度缩减等优化可能在某些场景引入额外指令，结果以实测为准。

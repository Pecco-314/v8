## 1. gen_metadata_info.py

### 功能

解析 JavaScript 文件，提取函数字节码偏移，生成类型注解模板。

### 使用方法

```bash
python3 scripts/gen_metadata_info.py <js_file>
```

**示例**：
```bash
python3 scripts/gen_metadata_info.py test/mjsunit/compiler/typeinjector-getstr.js
```

### 输出

在 `metadata/` 目录生成 `<file_hash>.tdl` 模板文件：

```
# 自动生成的模板
# File: test/mjsunit/compiler/typeinjector-getstr.js
# Hash: a1b2c3d4...

123 @params  @ret 
456 @params  @ret 
789 @params  @ret 
```

### 实现原理

1. 计算文件 SHA256 哈希
2. 使用 `--print-bytecode` 标志运行 d8
3. 解析字节码输出，提取函数偏移
4. 生成 TDL 模板

**核心代码**：
```python
def get_bytecode_offsets(js_file):
    result = subprocess.run(
        ['./out.gn/x64.release/d8', '--print-bytecode', js_file],
        capture_output=True, text=True
    )
    
    offsets = []
    for line in result.stdout.splitlines():
        if 'BytecodeOffset' in line:
            offset = extract_offset(line)
            offsets.append(offset)
    
    return offsets
```

### 后续步骤

手动编辑生成的 `.tdl` 文件，填写类型注解。

## 2. clean_metadata.py

### 功能

清理 `metadata/` 目录中孤立的元数据文件（对应的测试文件已删除）。

### 使用方法

```bash
./scripts/clean_metadata.py
```

### 实现原理

1. 遍历 `metadata/*.tdl` 文件
2. 检查对应的 JavaScript 文件是否存在
3. 如果不存在，删除元数据文件

**核心代码**：
```python
def clean_metadata():
    for tdl_file in glob.glob('metadata/*.tdl'):
        hash_value = extract_hash_from_filename(tdl_file)
        
        # 在测试目录查找对应文件
        found = False
        for js_file in glob.glob('test/**/*.js', recursive=True):
            if compute_hash(js_file) == hash_value:
                found = True
                break
        
        if not found:
            os.remove(tdl_file)
            print(f"Removed orphaned: {tdl_file}")
```

## 3. generate_graphs.py

### 功能

生成 TurboFan 优化前后的中间表示图，用于可视化和对比。

### 使用方法

```bash
./scripts/generate_graphs.py <js_file>
```

**示例**：
```bash
./scripts/generate_graphs.py test/mjsunit/compiler/typeinjector-getstr.js
```

### 输出

在工作目录生成 JSON 格式的图文件：

```
turbo-<function_name>-0.json         # EarlyOptimization 阶段
turbo-<function_name>-1.json         # TypeInjector 阶段后
turbo-<function_name>-2.json         # TypedLowering 阶段后
```

### 地址规范化

自动规范化内存地址，使输出稳定可比较：

```python
def normalize_address(line):
    """将地址 0x563f4b2c8080 替换为 0xNORMALIZED_ADDRESS"""
    return re.sub(r'0x[0-9a-f]+', '0xNORMALIZED_ADDRESS', line)
```

**为什么需要规范化**：
- V8 每次运行分配的地址不同
- 规范化后可以用 `diff` 工具比较图结构
- 便于版本控制和自动化测试

### V8 标志

使用以下标志生成图：

```bash
--trace-turbo-graph 
--trace-turbo-scheduled 
--trace-turbo-reduction 
--turbo-profiling
```

## 4. analyze_optimization.py

### 功能

统计优化前后节点数量变化，生成结构化的优化报告。

### 使用方法

```bash
python3 scripts/analyze_optimization.py
```

### 输出

更新 `metadata/优化效果.md`，包含：
- 每个测试函数的节点统计
- 消除的具体节点
- 优化效果量化

**示例输出**：
```markdown
## getStr 优化效果

**优化前节点数**: 45
**优化后节点数**: 42
**消除节点数**: 3

### 消除的节点
- CheckString (#37): receiver 类型为 str
- CheckString (#42): 参数类型为 str

### 节点变化
- 减少: CheckString (-2)
- 增加: ChangeTaggedToTaggedPointer (+2)
```

### 实现原理

1. 解析 `turbo-*-0.json` (优化前) 和 `turbo-*-final.json` (优化后)
2. 统计节点类型出现次数
3. 计算差异
4. 生成 Markdown 报告

**核心逻辑**：
```python
def analyze_graph(json_file):
    with open(json_file) as f:
        graph = json.load(f)
    
    node_counts = {}
    for node in graph['nodes']:
        opcode = node['opcode']
        node_counts[opcode] = node_counts.get(opcode, 0) + 1
    
    return node_counts

def compare_graphs(before, after):
    diff = {}
    for opcode in set(before.keys()) | set(after.keys()):
        before_count = before.get(opcode, 0)
        after_count = after.get(opcode, 0)
        if before_count != after_count:
            diff[opcode] = after_count - before_count
    return diff
```

## 5. verify_tests.py

### 功能

验证所有测试的优化效果是否符合预期，用于回归测试。

### 使用方法

```bash
./scripts/verify_tests.py
```

### 验证内容

1. **测试是否通过**: 运行 d8 执行测试
2. **节点是否消除**: 检查特定节点在优化后是否不存在
3. **类型传播正确性**: 验证替换节点类型正确

### 预期配置

在脚本中定义每个测试的预期：

```python
EXPECTED_OPTIMIZATIONS = {
    'typeinjector-getstr.js': {
        'eliminated_nodes': ['CheckString'],
        'min_eliminated_count': 2
    },
    'typeinjector-addrawint32.js': {
        'eliminated_nodes': ['CheckedInt32Add', 'CheckedInt32Div'],
        'min_eliminated_count': 4
    },
    'typeinjector-processpoint.js': {
        'eliminated_nodes': ['CheckedUint32Bounds'],
        'min_eliminated_count': 2
    }
}
```

### 输出

```
✓ typeinjector-getstr.js: PASS
  - Eliminated 2 CheckString nodes
✓ typeinjector-addrawint32.js: PASS
  - Eliminated 4 CheckedInt32* nodes
✗ typeinjector-process.js: FAIL
  - Expected elimination not found
```

## 工具链使用流程

### 新测试完整流程

```bash
# 1. 编写测试
vim test/mjsunit/compiler/typeinjector-mytest.js

# 2. 生成元数据模板
python3 scripts/gen_metadata_info.py test/mjsunit/compiler/typeinjector-mytest.js

# 3. 手写类型注解
vim metadata/<hash>.tdl

# 4. 生成优化图
./scripts/generate_graphs.py test/mjsunit/compiler/typeinjector-mytest.js

# 5. 分析优化效果
python3 scripts/analyze_optimization.py

# 6. 验证测试
./scripts/verify_tests.py

# 7. 运行测试
./out.gn/x64.release/d8 --test test/mjsunit/compiler/typeinjector-mytest.js
```

### 批量验证

```bash
# 清理孤立元数据
./scripts/clean_metadata.py

# 验证所有测试
./scripts/verify_tests.py

# 更新优化报告
python3 scripts/analyze_optimization.py
```

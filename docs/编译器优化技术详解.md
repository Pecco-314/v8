# 编译器优化技术文档

本文档说明 TypeInjector 在 TurboFan 管线中实现的具体优化技术。

## 实现文件

**核心实现**: `src/compiler/type-injector.cc`
**头文件**: `src/compiler/type-injector.h`
**类型存储**: `src/compiler/type-storage.h`
**测试**: `test/mjsunit/compiler/typeinjector-*.js`

## 优化策略概览

TypeInjector 采用**类型信息驱动的节点替换**策略，在已知节点类型时，将带检查的节点替换为无检查的等价节点或直接的硬件操作。

```
带类型检查的节点 + 静态类型信息 → 无检查节点 / 硬件指令
```

## 基础类型检查消除

### CheckString 消除

**原节点**: `CheckString` - 运行时验证值为字符串
**替换为**: `ChangeTaggedToTaggedPointer` - 无检查的指针转换

```cpp
Reduction TypeInjector::ReduceCheckString(Node* node) {
    Node* input = node->InputAt(0);
    const TypeAST* type = GetNodeType(input);
    
    if (type && type->kind == TypeAST::Str) {
        Node* replacement = graph()->NewNode(
            simplified()->ChangeTaggedToTaggedPointer(), input);
        SetNodeType(replacement, type);
        return Replace(replacement);
    }
    return NoChange();
}
```

**测试**: `test/mjsunit/compiler/typeinjector-getstr.js`

### CheckNumber 消除

**原节点**: `CheckNumber` - 运行时验证值为数值
**替换为**: `ChangeTaggedToTaggedPointer`

类似 `CheckString`，当输入类型为 `Num` 时消除检查。

### CheckBounds 消除（Tuple）

**原节点**: `CheckedUint32Bounds` - 数组边界检查
**优化条件**: 
- 数组类型为 `Tuple`
- 索引为编译时常量
- 索引在 `[0, tuple_size)` 范围内

**实现**：
```cpp
if (const_index && array_type->kind == TypeAST::Tuple) {
    int idx = *const_index;
    if (idx >= 0 && idx < tuple_size) {
        ReplaceWithValue(bounds_check, index);  // 直接消除
        PropagateElementType(bounds_check, array_type->children[idx]);
    }
}
```

**测试**: `test/mjsunit/compiler/typeinjector-processpoint.js`

## 数值类型设计决策

### 为何只使用 Number 而不区分 Smi 和 HeapNumber

**TypeScript 兼容性考虑**：
- TypeScript 只有 `number` 类型，不区分整数和浮点
- 如果 TDL 允许手动标注 `smi` 类型，会与 TypeScript 类型系统不兼容
- 未来从 TypeScript 自动生成 TDL 时无法映射

**类型不稳定性问题**：

即使允许手动标注 `smi`，也无法保证运行时类型不变化。

**危险示例 1 - 累加溢出**：
```javascript
// 假设允许标注为 smi
function sum(arr) {  // arr: Array<smi>
    let total = 0;   // total: smi
    for (let x of arr) {
        total += x;  // 可能溢出！
    }
    return total;
}

// 如果 arr = [1000000000, 1000000000, 1000000000]
// total 会超出 Smi 范围 (2^30 - 1)，被转换为 HeapNumber
// 但我们的类型系统认为 total 仍是 smi，导致优化错误
```

**危险示例 2 - 除法结果**：
```javascript
function average(a, b) {  // a: smi, b: smi
    return (a + b) / 2;   // 结果可能是浮点数！
}

// average(5, 6) 返回 5.5，不是 Smi
// 如果后续代码假设返回值是 Smi 进行位运算，会出错
```

**V8 内部动态转换**：
- Smi 范围: `[-(2^30), 2^30 - 1]` (约 ±10亿)
- 超出范围自动转换为 HeapNumber
- 任何浮点运算结果都是 HeapNumber
- 转换对 JavaScript 代码透明，但对编译器优化致命

**结论**: `num` 类型统一处理所有数值，安全但保守

### RawInt32 的必要性

**封闭性需求**：

为了实现高性能整数优化，需要一个**类型封闭**的整数类型：
- 运算结果仍为同类型
- 不会发生自动类型转换
- 可以安全使用硬件指令

**RawInt32 的保证**：
```
RawInt32 + RawInt32 → RawInt32 (或中断/分支处理)
```

**与 Smi 的区别**：

| 特性 | Smi | RawInt32 |
|------|-----|----------|
| 值域 | `[-(2^30), 2^30-1]` | `[-(2^31), 2^31-1]` |
| 溢出行为 | 自动转换为 HeapNumber | **守护分支处理** |
| 除法结果 | 可能返回 HeapNumber | **整数除法语义** |
| 类型稳定性 | 不保证 | **保证封闭性** |

**为何必须重新定义除法**：

标准 JavaScript 除法的问题：
```javascript
5 / 2 === 2.5  // 返回浮点数，破坏类型封闭性
```

RawInt32 除法语义：
```cpp
// 整数除法：截断小数部分
5 / 2 → 2  (不是 2.5)

// 特殊情况处理：
// 1. 除零：不能让系统中断，需要守护分支返回安全值
0 / 0 → 0 (或其他约定值)

// 2. 溢出：INT_MIN / -1 会溢出，需要特殊处理
-2147483648 / -1 → 守护分支返回 INT_MIN (或其他约定值)
```

**实现策略**：
- 生成分支检查除数是否为 0 和是否溢出
- 安全路径使用硬件 `Int32Div` 指令
- 不安全路径返回预定义的安全值
- 保证既不系统中断，也不发生类型变化

## RawInt32 整数优化

RawInt32 是项目的核心创新，通过类型封闭性实现接近硬件的整数运算。

### CheckedInt32Add → Int32Add

**原节点**: `CheckedInt32Add` - 带溢出检查的加法
**替换为**: `Int32Add` - 直接硬件加法指令

```cpp
Reduction TypeInjector::ReduceCheckedInt32Add(Node* node) {
    Node* left = node->InputAt(0);
    Node* right = node->InputAt(1);
    
    if (BothInputsAreRawInt32(left, right)) {
        Node* add = graph()->NewNode(machine()->Int32Add(), left, right);
        return Replace(add);
    }
    return NoChange();
}
```

**测试**: `test/mjsunit/compiler/typeinjector-addrawint32.js`

### CheckedInt32Div → Int32Div + 守护分支

除法需要特殊处理两个异常情况：
1. **除零**: `divisor == 0`
2. **溢出**: `INT32_MIN / -1` 导致结果溢出

**实现策略**: 生成分支，安全路径使用硬件除法，不安全路径回退

```cpp
Reduction TypeInjector::ReduceCheckedInt32Div(Node* node) {
    Node* dividend = node->InputAt(0);
    Node* divisor = node->InputAt(1);
    
    if (!BothInputsAreRawInt32(dividend, divisor)) {
        return NoChange();
    }
    
    // 构建安全条件
    // safe_condition = (divisor != 0) && !(dividend == INT_MIN && divisor == -1)
    
    Node* branch = graph()->NewNode(common()->Branch(), safe_condition, control);
    Node* if_safe = graph()->NewNode(common()->IfTrue(), branch);
    Node* if_unsafe = graph()->NewNode(common()->IfFalse(), branch);
    
    // 安全路径：直接硬件除法
    Node* safe_div = graph()->NewNode(machine()->Int32Div(), dividend, divisor, if_safe);
    
    // 不安全路径：生成回退值（通常为 0 或 INT32_MIN）
    Node* unsafe_result = GenerateSafeFallback(dividend, divisor, if_unsafe);
    
    // 合并两个控制流
    Node* merge = graph()->NewNode(common()->Merge(2), if_safe, if_unsafe);
    Node* phi = graph()->NewNode(
        common()->Phi(MachineRepresentation::kWord32, 2),
        safe_div, unsafe_result, merge);
    
    return Replace(phi);
}
```

**生成的IR结构**：
```
Branch(safe_condition)
├─ IfTrue → Int32Div → Merge
└─ IfFalse → Constant(fallback) → Merge
            ↓
          Phi (结果)
```

**测试**: 
- `test/mjsunit/compiler/typeinjector-addrawint32.js` (包含除法测试)
- 溢出测试: `-2147483648 / -1`
- 除零测试: `x / 0`

### 其他算术操作

| 原节点 | 替换节点 | 特殊处理 |

| CheckedInt32Sub | Int32Sub | 无 |
| CheckedInt32Mul | Int32Mul | 无 |

## 对象字段访问优化

### LoadField 类型传播

当对象类型为 `obj{...}` 时，`LoadField` 节点的结果类型可以精确确定。

```cpp
void TypeInjector::PropagateLoadFieldType(Node* load_field) {
    Node* object = load_field->InputAt(0);
    const TypeAST* object_type = GetNodeType(object);
    
    if (object_type && object_type->kind == TypeAST::Obj) {
        // 根据字段名查找类型
        std::string field_name = GetFieldName(load_field);
        for (const auto& child : object_type->children) {
            if (child.field_name == field_name) {
                SetNodeType(load_field, &child);
                break;
            }
        }
    }
}
```

**效果**: 后续使用该字段的操作可以利用精确类型进行进一步优化

## 内建函数调用优化

### 内建函数签名

文件 `metadata/builtin.tdl` 包含常用内建函数的签名：

```
1338 @params num @ret str      # Number.prototype.toString
1377 @params any @ret str      # Object.prototype.toString
```

### JSCall 返回类型推导

```cpp
void TypeInjector::ReduceJSCall(Node* call) {
    int builtin_id = GetBuiltinId(call);
    if (builtin_id >= 0) {
        auto signature = TypeStorage::Get()->GetBuiltinSignature(builtin_id);
        if (signature) {
            SetNodeType(call, &signature->return_type);
        }
    }
}
```

## 类型传播机制

### 节点类型标记

使用 `NodeAuxData` 存储节点类型信息：

```cpp
class TypeInjector {
private:
    NodeAuxData<const TypeAST*> node_types_;
    
    void SetNodeType(Node* node, const TypeAST* type) {
        node_types_.Set(node, type);
    }
    
    const TypeAST* GetNodeType(Node* node) {
        return node_types_.Get(node);
    }
};
```

### 传播规则

1. **函数参数**: 从 TypeStorage 加载签名，标记 `Parameter` 节点
2. **返回值**: 标记 `Return` 节点输入
3. **替换节点**: 继承原节点类型
4. **LoadElement/LoadField**: 根据容器类型推导元素类型
5. **算术运算**: RawInt32 操作结果仍为 RawInt32

## 技术讨论

### CheckMaps 不消除的原因

**问题**: Map (Hidden Class) 不稳定
- Tuple 的 Map 取决于元素实际类型（Smi vs HeapNumber）
- Class 的 Map 随字段类型变化（Map Transition）

**实验证据**: `docs/Tuple Class隐藏类分析.md`
- `[1, 2]` 的 Map: `0x63987ecab3d0`
- `[1.5, 2.5]` 的 Map: `0x6143dafae3d0`

**策略**: 保留 CheckMaps，在其后优化 LoadElement/LoadField

### 不区分 interface 和 class

**原因**: 
- Class 的 Hidden Class 仍由字段值类型决定，不稳定
- 优化效果与 interface 相同，增加复杂度收益有限

**当前处理**: 统一为 `obj{...}` 类型
